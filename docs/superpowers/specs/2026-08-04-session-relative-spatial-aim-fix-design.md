# 3DGS 会话相对空间点修正设计

## 目标

3DGS 拍摄页打开后，以收到的第一帧有效 CoreMotion 姿态建立一次性的会话坐标系。第一个点位于此时相机正前方，其余七个点按 45° 间隔分布在同一水平圆周。用户站在原地旋转手机时，点位保持在该会话空间中，只因相机视角变化而进入或离开屏幕。

本功能不使用 AR，不估算手机平移，也不使用磁北或真北。点位方向只在本次页面会话中固定。

## 根因

当前实现先把 CoreMotion 绝对姿态转换成 SceneKit 相机姿态，再用首帧计算一个额外的水平航向修正。绝对坐标、设备坐标、SceneKit 坐标以及航向修正混合在同一条链路中，真机姿态变化时无法可靠表达“相对于启动姿态的相机旋转”，表现为点位接近屏幕坐标而非会话空间坐标。

## 坐标模型

保存首个有效 CoreMotion 四元数 `q0`。每个后续姿态为 `qt`，SceneKit 相机使用以下会话相对旋转：

`qCamera = q0 * inverse(qt)`

该定义满足：

- 首帧 `qt == q0` 时，`qCamera` 为单位四元数，第一个点位于 SceneKit 相机正前方 `-Z`。
- 手机原地旋转时，只更新 `cameraNode.orientation`。
- `aimRootNode` 和八个点的世界坐标创建后不再旋转或重算。
- 转动一周回到初始姿态时，相机重新接近单位姿态。

四元数在使用前归一化。CoreMotion 四元数的双覆盖形式 `q` 和 `-q` 表示同一姿态，不影响旋转结果。

## 点位和交互

- 八个点保持半径 2.5 米、水平间隔 45°。
- 第一个点为 `(0, 0, -2.5)`。
- 仍然一次只显示当前点。
- 当前点进入屏幕中心阈值并连续保持 0.8 秒后，播放完成动画并显示下一个点。
- 点位推进只改变可见节点，不改变任何点的空间坐标。
- 不触发拍照或录像。

## 生命周期

- 页面首次进入或完整重置时清除首帧姿态和点位进度。
- 进入后台时停止 CoreMotion 和渲染。
- 回到前台时重新建立首帧姿态，但保留当前点位序号，防止 CoreMotion 参考系重启造成跳变。
- 未收到有效姿态时隐藏空间点覆盖层。

## 测试

新增纯四元数测试，覆盖：

1. 首帧与当前帧相同时返回单位旋转。
2. 当前姿态相对首帧旋转 45° 时，相机产生方向相反的 45° 观察旋转，使固定点从中心移出。
3. 当前姿态旋转 360° 后回到单位旋转。
4. 更新相机姿态不会修改八个点的既有坐标。
5. 现有点位顺序、0.8 秒停留和生命周期测试继续通过。

## 非目标

- 不跟踪手机左右或前后平移。
- 不把点绑定到磁北、真北或地图坐标。
- 不引入 ARKit、视觉里程计或相机特征点追踪。
